# CRM AI photo estimates

This feature prepares a **suggestion for a person to review**, not an automatically approved or sent quote. It is disabled until the feature is deployed and an administrator deliberately completes the OpenAI setup below. No billing, credential, production setting, or live OpenAI request was enabled by building it. Tests use fictional data and simulated providers; a real provider request and physical-phone workflow have not yet been verified.

## Preparing a draft

1. Wait for **Synced across devices**, open **Estimates → Photo estimate with AI**, and choose an existing client and a service. The optional property and client selection stay in the CRM and are not separately sent to OpenAI. If their names or addresses appear in the description, rate names or images, however, those details are sent as part of that material. Avoid unnecessary personal or sensitive information, and obtain any needed permission to share the photos.
2. Describe the requested work and provide known measurements, access details and other conditions; choose **1–3** photos, each no larger than 20 MB. Thumbnails show what was chosen. JPEG, PNG, WebP and HEIC/HEIF are accepted if the device can decode them; if a HEIC photo fails, choose a JPEG or PNG. Selected pictures are resized to at most 1,200 pixels on the long edge and re-encoded as JPEG on the device; embedded metadata is not copied. Text, addresses, people and other identifying details *visible in the picture* remain visible. The browser sends the re-encoded images, not the filenames or original files. The prepared JPEGs are bounded at 750,000 bytes each so the JSON request fits below the Vercel Function payload limit.
3. **Rates are optional.** The original starter rates are placeholders, not real prices, and cannot be used here unchanged. In **Rates**, replace the entire card with actual, verified prices; use `name | price`, one line per rate, with no duplicates and up to two decimal places. To use a saved card in an AI draft, explicitly check the box confirming that all of its prices are current. Only the **names and numeric identifiers** are sent to OpenAI, not their prices. A suggested rate match is mapped back to the saved price on the device. A name match, unit, quantity or applicability can still be wrong. If there is no verified card or an item cannot be matched, its price stays blank for manual entry. If the card changes before the editor opens, matching prices are left blank; if it changes in the editor, saving is blocked until the prices are reviewed again. Rates and totals are always the person's responsibility.
4. Read and check the disclosure for **each request**, then tap **Generate draft**. This sends the selected, prepared photos, work description, service and (only if selected) rate names to OpenAI. It may incur separately billed API charges. ChatGPT Plus does not cover general API usage. No request is sent by choosing photos, and no customer is contacted. The app does not automatically retry; closing after sending cannot guarantee the provider stops processing or charging. If the response is missing, check OpenAI usage before deliberately trying again.
5. Review the suggested scope, quantities, matching rate names, questions and cautions. Photos cannot reliably reveal size, measurements, hidden damage, safe access, site restrictions, supplies or all required work. Take measurements or inspect as needed. The AI is not a professional site assessment and can be wrong even when it returns a number or rate match.
6. Tap **Review in estimate editor**. This opens an **unsaved Draft** in the existing estimate editor. Check and edit the client, property, scope, quantities, prices, customer notes and total; tax is not automatic. Enter any missing quantity or price. Confirm the review checkbox and explicitly **Save estimate**. If anything changes after the checkbox was checked, review and check it again. Saving does not send the estimate or schedule a job. Later, the normal **View → Copy text / Print / PDF** controls require a separate manual action; schedule only through the existing reviewed workflow.

The AI summary, questions, cautions, line explanations and work description are copied to editable **team-only notes** in the editor, not customer-facing notes. Team-only means not shown on the estimate document; all authenticated CRM team accounts have broad access to shared records, and a saved estimate and its team-only notes are included in CRM JSON backups. If this text exceeds 5,000 characters, the app warns before shortening it. Cancelling the suggestion/editor does not create a CRM estimate. AI-selected photos are not saved as job photos or included in backups; the separate Before / after job-photo feature is unchanged. Existing job quotes are not changed by generating a photo draft.

## Privacy, cost and access

- OpenAI's Responses API is called with `store: false`, but this is **not** a promise of zero provider retention. OpenAI's [API data policies](https://platform.openai.com/docs/guides/your-data) describe abuse-monitoring retention and other controls; API data is not used to train models by default unless the organization opts in. Vercel is also involved in receiving the request. The application code does not intentionally log or persist the photos or provider request. Review the providers' current policies before sending customer information.
- The server checks the Supabase bearer token against the CRM project and rejects anonymous or unverified users. **Every authenticated CRM team user can use the feature once enabled.** There is no per-user spending quota or durable application-level rate limiter; a user with valid CRM access can call the endpoint directly. Protect CRM accounts and enforce low model request/token limits and a spend limit in the dedicated OpenAI project. The disclosure checkbox is a user-interface confirmation, not a defense against a malicious authenticated user.
- This implementation uses `gpt-5.4-mini` with high-detail image input and a bounded output. Image inputs and text count toward API usage. Pricing and available models can change; see [model pricing](https://developers.openai.com/api/docs/models/gpt-5.4-mini) and [image input costs](https://developers.openai.com/api/docs/guides/image-cost-calculator). It cannot promise a fixed cost per quote.
- ChatGPT and the OpenAI API can use the same OpenAI account login, but API billing is separate from ChatGPT Plus. Plus does not itself provide general API usage or the separate Pro/Business subscription API credit benefit. Never enter a password or API key into this CRM, repository, issue, pull request, or chat.

## Administrator setup — only after the owner approves API costs

These are instructions for a later, explicitly approved setup; they have **not** been performed by this change.

1. Review and deploy the code through the normal release process. Until configured, requests fail closed with a setup message and do not reach OpenAI. Keep production disabled until ready. A preview can share the **live CRM database**; do not save, delete, or otherwise modify live records as a test.
2. The owner can sign in to the [OpenAI API platform](https://platform.openai.com/) using the same OpenAI account used for ChatGPT, if desired. Decide whether to enable separate API billing or purchase prepaid credits; **do not enable either without the owner's approval**. Review any auto-recharge setting and disable it unless explicitly wanted. Prepaid processing delays can occur; do not assume a prepaid balance is a perfectly instantaneous cutoff.
3. Create a dedicated API project and an expiring project key restricted to the required endpoint/model where the platform supports it. In the project's Limits, set conservative model request/token limits, a monthly spend amount, alerts and **Enforce a hard limit**. A spend alert or an unenforced budget alone does not stop requests. OpenAI says enforcement is not instantaneous and recorded spend may slightly exceed a hard limit; consult [OpenAI's current project and spending guidance](https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform). Monitor usage and rotate or revoke the key when appropriate.
4. In the **primary frontend Vercel project**, add `CRM_OPENAI_API_KEY` as a **sensitive server-side environment variable**, with the dedicated key entered directly into Vercel by the administrator. Set `AI_QUOTES_ENABLED` to the exact value `true` only when ready. Set these only for the intended deployment environments; do not put the key in `REACT_APP_` variables, browser code, Git, logs, screenshots or chat. Vercel environment changes require a new deployment to take effect. To stop new use, disable the switch, redeploy, and revoke the provider key if immediate provider-side cutoff is needed.
5. After approval, use an explicitly authorized low-cost, fictional-photo live test and check OpenAI usage. Separately test the real phone workflow. This change's automated tests use mocked responses only; they cannot guarantee account/model access, provider schema behavior, charging, network timeouts or production Vercel configuration. Do not test by creating or changing a real customer record without the owner's permission.

The Vercel function limits request sizes, requires explicit consent in the payload, sends no server credentials to the browser, validates the structured model output independently and returns a no-store response. These controls do not eliminate prompt injection, estimation errors, provider retention, spending risk, or the existing CRM's shared-team access model. Use one device at a time for saves and wait for the existing sync indicator; cross-device writes are not transactional.
