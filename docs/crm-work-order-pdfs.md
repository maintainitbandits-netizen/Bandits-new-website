# Importing AppFolio work-order PDFs

This is a **manual, one-way import**, not an AppFolio connection. The person using the CRM signs in to AppFolio themselves and downloads each work order through the Vendor Portal's **Download PDF** button. The importer does not ask for AppFolio credentials, read notification links, accept or decline work, or change AppFolio. Check AppFolio for acceptance requests, estimates, holds, cancellations and changes before acting on an order. A later AppFolio change does not update the CRM job.

## Before importing

- Add each property manager as a CRM client first. Wait until the header says **Synced across devices**, make a private backup, and use one device at a time.
- Download one work order per PDF. In the CRM, choose **Import work order PDFs** and select several files in the device file picker. More files can be added to the same batch. The limit is **25 PDFs per batch**, **5 MB and 25 pages per PDF**, and 50,000 extracted text characters per PDF. Choose a smaller batch if the device cannot handle it.
- The file must contain selectable text. Image-only scans are not read; there is no OCR. Images, photo attachments, annotations and interactive PDF form fields are not imported. A page with no selectable text is flagged, but a page that has some text can still contain images or other material that is not extracted. Check the original PDF. Password-protected, invalid, oversized, unreadable or image-only PDFs are listed individually and do not prevent reviewing other files. The original PDFs and filenames are not saved with the jobs.
- The reader and its worker load from this website. PDF bytes and extracted text are processed in the browser and are not sent to AppFolio or a PDF service. Closing the dialog discards the unsaved review. Browser support and the phone's file picker still need real-device testing.

## Review and save

1. The work-order number, location and description are **suggestions**, not guaranteed fields: AppFolio PDF formats can vary, and a description suggestion may include only its first line. No real AppFolio work-order PDF has been supplied for validation. Compare every field against the original and correct it. The entire extractable text is placed in a second editable team-only field so important details are not silently discarded; text order may differ from the PDF. Remove information you do not need from both fields, particularly personal details, entry codes or links.
2. Choose the property-manager/client for each order. **Apply client to all** fills all readable rows and individual rows can still be changed. Enter the AppFolio work-order number, property/unit address and work description, and select a CRM service. The service defaults to **Other**, not a price or inferred service. Each readable PDF starts checked; uncheck any order you do not want to import. An unreadable file cannot be selected.
3. Leave the planned CRM date blank to create an **Unscheduled** job; it stays off routes. Entering a date creates a **Scheduled** CRM job for that day. This does **not** schedule or accept it in AppFolio. Source dates, statuses, deadlines and prices are not inferred. You can edit a job afterward, set a due-by or exact-day requirement, and schedule it when ready. An unscheduled job can appear in Due & overdue if you explicitly give it a valid requirement. To schedule one, use its **Schedule** button and choose a date; it is appended after existing stops on that day.
4. Select **Import selected jobs**, check the number of scheduled and unscheduled jobs in the confirmation, and confirm. No existing records are intentionally replaced. Unselected or unreadable PDFs are not added. Keep the page open until the sync indicator says **Synced across devices**, then verify the jobs. If local storage fails, use Backup and keep the page open; if a server write fails, the existing outbox retries. A batch consists of individual record writes, not a transaction, so another device can temporarily see only part of it.

The work description and extracted work-order text are stored in separate **team only** fields, separately from the job's normal customer-facing Notes. Both are editable in the job, accessible to **all authenticated CRM team accounts** and included in JSON backups; there is no per-client or per-user access isolation. Neither appears on the CRM's quotes or invoices. Imported jobs have no price; enter one before opening their quote or invoice, so an unset price is not accidentally presented as $0. The original PDF itself is not stored or backed up. If you later set a repeat for a scheduled imported job, the new occurrence does not copy its AppFolio number, description or extracted work-order text.

Duplicate checking matches an imported work-order number (ignoring case, a leading `#` and whitespace) plus the property-manager/client selected at the original import. A duplicate within the batch or an existing imported job must be unchecked or corrected. Identical numbers for different property managers are allowed. The original manager identity remains attached even if the job is later reassigned to a different CRM client. Jobs entered before this feature without AppFolio metadata, different number formats and simultaneous imports on separate devices can still create duplicates. Re-importing does not update an existing job; edit it manually instead. Check for duplicates yourself and use one device at a time.

## Implementation and verification

`frontend/public/crm-pdf.mjs` uses the locally hosted legacy builds from **pdfjs-dist 6.4.299**, `frontend/public/crm-pdfjs/`, under the included Apache 2.0 license. The original npm files are pinned without changing the frontend package manifests. SHA-256: `pdf.min.mjs` `bccc24ea711db8e44503629519904a5292d73b9daaa214bbe7cdcc282b0f4259`; `pdf.worker.min.mjs` `145d2dd3ab0c86151011dba95acfa2d5336e2accd59388ea43dbee0efddaaec6`. The importer extracts text only, does not render or execute PDF scripts, and disables PDF.js scripting, XFA and WebAssembly options. Keep the library updated when security fixes are released.

Automated tests generate fictional PDFs and use mocked CRM records with all browser network requests intercepted. They verify multi-select, review, local reading, duplicate prevention, errors, cancellation, scheduling and retry behavior. They do not verify a real AppFolio PDF layout or perform a live signed-in import. Before relying on extraction, test with a redacted or fictional representative PDF and review the saved jobs; never put real customer PDFs in the repository or public test fixtures.
